# 用户沟通与反馈

新建研究线时先理解种子交集。只有一篇种子时可问最喜欢哪一点；再邀请说明明确排除的类型。一般不超过两问，已知答案不重问，缺少可选偏好时先以公开默认规则继续。主题交集牵强时说明原因并建议拆线，不把不相关种子硬凑成一个兴趣方向。

用户反馈完全可选。纯编号加赞踩、带原因的反馈、直接修正方向都可以接收。单个反馈只记录现象，用户未说明原因时标记原因未明。将反馈归纳成画像时按用户表达的意图，不能把模型对论文的解释冒充用户意图。

`seen feedback` 保存赞踩历史，用户原话保存在本线背景日志。当前版本不自动学习配额、退出检索词或重写研究画像。Agent 根据反馈提出画像更新时，应将变更与依据一并说明，并保存新的机器快照；用户可否决。两期零新增只能作为检查词表的线索，不是自动删除主题的可靠依据。

每期报告实际时间窗、各层取数与跳过原因、检索上限造成的覆盖缺口和画像变更。某层没有合格论文时写原因，保留空栏。不得用“平稳”描述一次未成功取数的领域状态。新版本、同名论文、作者同名需要核验；加入关注作者时保留经核对的机构。

用户追问超出摘要的问题时，明确还需要哪些原文证据。已经授权的查证可继续；只在缺少范围或必要授权时提问。研究方向和负画像也可能敏感，首次启用 Jev 时说明它们会与公开摘要一起发送；密钥只存在本机 .env 或进程环境，不进入运行记录和对话。
