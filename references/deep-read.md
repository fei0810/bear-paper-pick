# deep-read 簇解读规范（v1）

事件驱动的五层论文解读。挂载于 bear-sift 作为线内 deep-dive 能力；本文件自足，脱离推荐流也可独立执行。
设计定稿 2026-09-19：解读单元是事件/簇（单篇=簇的退化形态）；五层原料；机器备原料出草稿、不替人下定论；层权重靠反馈逐轮调。
样例：references/deep-read-example.md（2026-05-19 Nature AI4S 三篇事件回测产出，演示承重标注、候选坐标轴与存疑清单的完整填法）。
版本：v1（2026-09-19：设计树两轮用户批准 + Nature 事件回测；层权重首次校准待用户逐层反馈）。

## 定位与分工

- **解读单元是事件/簇，不是单篇论文**。单篇输入按簇的退化形态处理：同样走五层，但叙事层会很薄——如实呈现薄，不硬凑。
- **机器产出**：五层原料（每条带承重标注）、事件时间线草稿、候选坐标轴 2~3 个、扣子候选清单。
- **人做**：选坐标轴、定扣子、下判断与预测。机器不输出成品解读稿。
- 反幻觉纪律继承 SKILL.md：标题/日期/作者/DOI 从 API 原始 JSON 提取（先存盘再解析），禁止模型转写；新闻与博客信息存原始 URL 与抓取日期。候选池只支持书目信息和摘要级描述，具体实验结果、融资、合作、审稿意见、临床注册与社区反响必须分别保留直接来源。
- 来源分级并在文中标注：同行评审与编辑材料=官方；公司博客/自述=**自报**（单方信源，须写明）；X/社区=民间反响。

## 五层原料与取数路径

### 1. 学术层
- 多版本并集：定位簇内每篇的全部版本（预印本/正式版），locations 与 related_works **逐条核对标题**（related_works 有噪声，见 api-recipes.md），年份取最早
- 摘要；方法骨架（一段以内）；评测声称（数字照录原文）
- Peer review：期刊公开审稿材料给链接；未公开写「未公开」，不编造
- 终止：到此为止。引文网不展开（展开是推荐流的事）

### 2. 人物层
- 通讯 + 一作必查：`fetch.py author` 拿单位轨迹、近 3 年代表作、被引量级
- 出现「主推作者」信号才展开合作网：近期跨机构跳 / 方向突变 / 一人横跨簇内多篇
- 终止：能回答「为什么是这个人/团队做出这个」就停

### 3. 行业层
- 一轮即止：Google News RSS（公司名+产品名各一搜）+ 公司官方博客 + 医学类加 ClinicalTrials.gov
- OpenAlex funders 只作补充（实测常为空）
- 无融资/合作/药企接触信号时一句话带过，不硬凑；**自报信源必须标注**
- 终止：有量化信号（金额、家数、具体公司名）列出即止，不做尽职调查

### 4. 叙事与反响层
- 事件时间线：簇内全部版本日期 + 社论/新闻日期 + 外部事件（发布会、同刊配对）按时间排
- 社论配对：OpenAlex `type=editorial` + 同日同刊可查（实测可行）
- 反响：X/社区争论只在有明确信号时展开；存链接、概括两派主张各一句，不站队
- 终止：时间线排完、争论两方各一句即止

### 5. 实操层（条件层）
- 工具/软件类论文必选，其余跳过并注明原因
- 三级验证：**L0** 读文档判断声称能力 → **L1** 装得上、quickstart 跑得动 → **L2** 跑通真实 demo（设超时与资源上限）
- 跑不到 L2 如实记录卡点（依赖/算力/权限）——跑不动本身是关于「这工具对谁可用」的信息
- 终止：L2 通过或卡点记录完成即止，不做性能评测

## 终止规则总判据：承重测试

每层追到新信息不再改变对论文/事件的价值判断就停。原料区每条信息标 ⚖️（承重：直接影响判断）或 ·（背景：知道即可）。标注是机器初判，人可改。

## 事件检测（weekly 顺带跑；命中不自动动笔）

1. **同期成包**：同刊同期 ≥2 篇命中画像的论文
2. **论文+社论/新闻同日配对**（OpenAlex type=editorial / 同 ISSN 同日检索）
3. **关注作者或种子主题一周内 ≥2 篇共现**

命中 → 战报末尾提示「建议簇解读：<事件>」，等用户发话。

## 输出骨架（固定）

存 `线目录/deep-read/<日期>-<slug>.md`：

```markdown
# 解读包：<事件名> · <日期>
## TL;DR（三行）
## 事件时间线
## 五层原料
### 学术层
### 人物层
### 行业层
### 叙事与反响层
### 实操层（跳过须注明原因）
## 证据台账
每条承重信息对应一行：信息编号 ｜ 支持的句子或数字 ｜ 来源类型 ｜ 直接 URL 或 DOI ｜ 获取日期 ｜ 已核对范围。无直接来源的项目放入“存疑与没看懂”，不以 ⚖️ 标注。
## 候选坐标轴（2~3 个，各一句话说清怎么切开这一簇）
## 扣子候选（机器提的未决问题清单；留哪颗人定）
## 存疑与没看懂
## 层反馈区
学术 ｜人物 ｜行业 ｜叙事反响 ｜实操 —— 每层标 有用/噪声/缺失
```

## 反馈与层权重

- 每期解读包末尾邀请层反馈（邀请式，不追问）：哪层有用、哪层噪声、哪层缺东西
- 反馈落账进 profile.md「解读层权重」小节（五层初始等权）：👍 升权（该层默认更深一档）、👎 降权直至「一句话带过」
- 纪律与推荐配比同源：反馈日志 append-only，权重每次重算，禁止自由编辑

## 与推荐流的关系

- 解读完成后簇内论文登记 seen（防重推）
- 簇内命中画像主题的论文同时是推荐候选；解读引用不占 digest 名额
