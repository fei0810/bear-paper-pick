# Jev 摘要筛选策略

Jev 是主工作流的默认语义筛选引擎。候选公开字段与英文摘要，加上正负画像轴和逻辑形组成远程输入。画像本身可能透露研究方向；首次启用时应让用户了解这一点，已有同范围授权可继续使用。先运行 sift.py screen --plan-only 可无网络查看同一排序与预算下的完整 payload。真实 .env 和本地数据不进入发布包。

仅显式标记 `abstract_language=en`、有题名、ID 和限长摘要的候选可发送；标记来自数据源，不能为了补齐数量而猜测。S2 当前缺少语言字段，因此通常会跳过，而非因为来源名称被禁止。preflight 同时剔除种子、已推和同批重复项。摘要超过 24000 字符或切句超过 254 条会跳过，确保有限选项接口可接受。

问题集沿用 paper-radar-jev-v1，保留与前版可比性。每项题型、选择、取值、概率键、有限数值、概率合计和固定响应模型都校验。实际 API 会把数值舍入到两位小数，检查误差按每项 0.005 的舍入范围传播；非法标签、负概率、无穷和 NaN 仍拒绝。异常响应留在审计中，优先级归零且不缓存。

主流程 sift.py screen 固定 review。独立实验的 shadow 保存输入顺序；review 按可用层概率与 fit 构成的启发式排序。排序前仅将已通过舍入检查的层概率归一化，原始答案不变。此分数不是经用户校准的偏好概率、科学质量或推荐成功率。confidence 只描述返回分布，默认不设拦截阈值。经典标签须另有引用或历史证据，跨域标签须另写同构与迁移边界；两者都标记为需独立复核。

每条完成请求立即更新当前运行记录，失败时保存 failed_partial 与当前候选 ID。完成的运行文件不覆盖重用；缓存绑定候选、画像、问题及固定模型。缓存损坏可重新请求，输入文件损坏须报告。传输仅对有界的暂时性失败重试。Jev 不直接改写候选池或已推状态。screen 将其结果绑定到本期选题和 digest：分层差异、异常回答与未评估采用需要 screening_note，原始判断和采用说明一起进入交付。

当前数据只建立工程可用性与小样本行为诊断。未完成用户盲标、跨线留出评测、漏推评估和人工时间测量，因此不作性能提升声明。对照试验应冻结相同候选与画像，在看到结果前记录比较规则；缓存命中只能证明重放一致，模型稳定性必须另做独立请求。

TypeSafe 官方文档说明请求不用于训练，零数据留存取决于企业方案；不要把公开摘要边界误写成“没有任何研究信息外发”。条款以服务方当前文档为准。[模型说明](https://docs.typesafe.ai/models) [API 契约](https://docs.typesafe.ai/api) [Score 定义](https://docs.typesafe.ai/primitives/score)

`screening.json` 含本地画像与审计。候选或画像修改后须重新 screen；相同远程输入可命中缓存。基础模式通过显式参数生成同格式记录，并写明原因，不声称使用了 Jev。
