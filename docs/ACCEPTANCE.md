## 输入与隔离

从固定提交或运行包开始，只使用 README 与 Skill，隔离已有全局 Skill、历史缓存、私人研究线和环境变量。记录操作系统、Python 版本、宿主名称与版本、提交 ID、安装方式。用户自行提供合法 key；记录外发授权和请求上限，不收录密钥。

选择用户真实理解的研究方向以及一至三篇公开种子 DOI。建议第一次至多评估 10 篇候选，确认成本与输出后再扩大。冻结问题、研究画像和本期时间窗，不向负责执行的 Agent 提供预期推荐名单。

## 必须观察的行为

先看 Agent 能否仅凭文档正确安装或加载 Skill、理解研究目标、建立独立数据目录并核对种子。随后观察 plan 展示的真实外发内容是否与 rank 一致，Jev 默认参与筛选，缺摘要、种子与已推条目能否正确处理。

检查 `review.md` 是否真正影响最终选题，分层分歧与未评估采用是否有具体证据说明。逐篇核对真实来源、DOI、日期、理由边界和 BibTeX。完成一次交付后重复更新，确认不重复推送；修改画像后旧筛选记录应被拒绝，重新筛选后可继续。

分别覆盖缺少 key、上游失败、无合格摘要、调用上限导致 deferred，以及用户主动选择基础模式。失败记录不能被报告为完整 Jev 结果。升级代码后，研究线、已推和反馈应保留。Windows 或其他尚未测试的宿主单独记录，不从一个平台类推。

## 验收记录格式

每个宿主保存一份记录：提交 ID、环境、原始任务、隔离方式、数据目录、外发范围、请求数量与用量、实际产物、用户评价、问题、修复提交和复测结果。原始材料留在研究项目，公开报告只保留脱敏摘要与许可明确的素材。最终结论须区分通过、失败、未执行。

## 公开发布条件

至少一个声明支持的宿主通过完整用户流程；其他宿主如未实测，在兼容性说明中明确。离线回归和干净包检查通过，安装、隐私、费用及基础模式说明与实现一致，权利归属和许可已确认。发布标签绑定确切提交，安装包与校验和从该提交生成并读回；上传和发布需要当时明确的用户授权。
