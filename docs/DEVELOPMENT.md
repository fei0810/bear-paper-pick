# 当前开发状态

更新时间：2026 年 9 月 29 日。版本：1.9.0.dev1。状态：独立本地仓库开发快照，未公开发布。本文件是 Claude Code 和其他 Agent 接手的当前入口。

## 已确认决定

项目命名为 Bear Sift，Skill 与仓库目录为 `bear-sift`。Jev 是核心卖点，主流程使用 review；shadow 保留为比较工具。最终选择允许研究者判断，但分层变更、异常结果与未经评估的采用须保留说明。基础模式是显式后备路径，不静默冒充 Jev 成果。

源码独立维护，iCloud 研究项目保存画像、种子、候选、已推状态、密钥和原始运行证据。当前只初始化本地 Git，不创建远程仓库、不推送、不做公开 Release。新用户验收由后续 Claude Code 或其他 Agent 执行，本次开发不代替该验收。

许可采用 PolyForm Noncommercial 1.0.0，准确描述为源码可用、非商业许可。机构用途的例外按原文执行，不自造“禁止一切企业相关用途”的条款。

## 已实现的主流程

`fetch.py` 取数和验证元数据；`profile_snapshot.py` 维护结构化研究画像；`sift.py screen` 将固定规则预排的候选交给 Jev，默认最多 40 篇，单次上限 200 篇。筛选结果生成 `screening.json` 和 `review.md`。每个研究线目录复用缓存，预算之外的候选明确列为 deferred。

`screening.py` 校验本期画像、候选、远程输入指纹、typed answers 与排序记录，要求选题中的分歧说明。`sift.py validate/render/register` 使用同一筛选记录；digest 显示 Jev 判断和摘要句，回执绑定 `screening.json`。这是一致性和可追溯性检查，不是 API 来源的密码学证明或科学结论验证。

网络失败保存已完成请求和失败记录，主工作流不自动降级。修复后在新的输出目录重跑，相同输入复用缓存；若用户选择基础模式，记录原因。

## 数据与迁移

来源为 Paper Radar 1.8.0 本地交付版本，原目录和历史证据保留在维护者研究项目中。当前脚本入口由 `radar.py` 改为 `sift.py`；新交付要求提供 `--screening`。以前的已推状态、候选池和画像无需迁移，既有数据目录可保留旧名字。

`paper-radar-profile-v1`、`paper-radar-fetch-run-v1`、`paper-radar-jev-v1` 及已有 Jev 审计 schema 保持不变，避免无意义地失效缓存或重写历史。新筛选包采用 `bear-sift-screening-v1`，新交付采用 `bear-sift-delivery-v1`；register 仍可读旧 `paper-radar-delivery-v1` 回执。

本次从审阅版显式文件清单导入源码。包含摘要原文的旧 public_benchmark 不复制到公开仓库；原证据留在 iCloud。新用户验收应现场按公开 DOI 取数，若要提交完整第三方文本须先确认再分发许可。

本轮最终源码在 macOS 的 Python 3.12 与 3.14 均通过 58 项离线回归，其中 12 项覆盖新的筛选与交付行为。官方 Skill 格式校验通过，40 个公开文件的清单、文档链接、版本与凭据模式检查通过。运行包 29 文件、审阅包 40 文件，重复构建逐字节一致；干净解压后 CLI 入口与审阅包检查通过。测试使用合成响应，不需要真实 key，未调用 Jev API。GitHub Actions 已配置但尚未在线执行。不同宿主的新用户验收、真实 Jev 新工作流与独立推荐收益评估均未执行。

继承版本曾在 macOS 上完成 46 项离线测试及两条公开研究线的真实取数和 Jev 调用。24 篇主样本与宿主 Agent 预先标签一致 20 篇，规则基线与 Jev 的可纳入 top 5 打平。这些历史结果属于旧版本，且参考标签不是研究者独立盲标，不能视为新工作流或质量优势的验收。
